# Sakila DVD 租赁管理系统的设计与实现

## 第一章 系统需求分析

### 1.1 功能需求分析

Sakila DVD 租赁管理系统以 DVD 租赁店的日常运营为背景，目标是帮助店员高效处理影片租赁、归还、库存管理和客户服务。系统功能需求整体上主要有：用户登录、影片租赁与归还、客户管理、电影管理、演员管理、库存管理等。

根据功能需求分析，系统涉及两种角色：**店员（Staff）** 和 **经理（Manager）**，其中经理拥有店员全部权限并额外具备电影与演员管理权限。

#### 店员功能

店员负责 DVD 租赁店的日常业务操作：

- 租赁影片：选择客户 → 扫描库存拷贝 → 生成租赁记录 → 记录付款
- 归还影片：扫描归还拷贝 → 更新归还日期 → 判断是否逾期
- 客户管理：查询/添加/修改客户信息，维护客户地址
- 库存查询：按门店、影片查询当前在馆拷贝数量

#### 经理功能

经理除店员全部权限外，还负责内容管理：

- 电影管理：添加新片、修改影片信息、管理影片分类
- 演员管理：添加/修改演员信息、管理演员与影片的参演关系
- 店员全部功能：租赁处理、客户管理、库存查询

### 1.2 非功能需求分析

**系统的实用性**：系统设计注重简单实用，每个模块采用统一的"表单 + 按钮 + 表格"布局，用户无需培训即可上手。租赁流程两步完成：选客户 → 扫拷贝，归还一步完成。

**系统的稳定性**：基于 MySQL 8.0 InnoDB 引擎，利用事务保证租赁与付款的原子性。外键约束确保数据完整性（如不可删除有未归还记录的客户）。

**系统的开放性**：使用 Python 3.12 + tkinter 标准库构建，无需额外 GUI 框架，可在 macOS、Windows、Linux 上直接运行。

## 第二章 系统设计

### 2.1 系统架构

系统采用 **单体架构 + 多文件模块化** 设计。所有功能聚合在一个桌面应用中，数据存储在单个 MySQL `sakila` 数据库中。代码按业务模块拆分为独立文件：

```
sakila-management/
├── db.py              ← 数据库连接层
├── main.py            ← 登录入口 + 主界面路由
├── rental_ui.py       ← 租赁处理模块
├── customer_ui.py     ← 客户管理模块
├── inventory_ui.py    ← 库存管理模块
├── film_ui.py         ← 电影管理模块
└── actor_ui.py        ← 演员管理模块
```

**分层架构**：

```
┌──────────────────────────────┐
│      表示层 (tkinter GUI)     │
│  main.py  ←→ 各 _ui.py 模块  │
├──────────────────────────────┤
│      业务逻辑层               │
│  表单验证 · 租赁规则 · 权限控制 │
├──────────────────────────────┤
│      数据访问层 (db.py)       │
│  doSql() / querySql()         │
├──────────────────────────────┤
│      MySQL sakila 数据库       │
│  16 张表 · 外键约束 · 视图     │
└──────────────────────────────┘
```

### 2.2 系统功能模块设计

| 模块 | 功能描述 | 核心表 |
|------|---------|--------|
| 登录模块 | staff 表用户名/密码验证，登录后根据角色显示对应功能 | staff |
| 租赁处理 | 租出（选客户 → 选拷贝 → 生成 rental + payment）、归还（更新 return_date） | rental, inventory, payment, customer |
| 客户管理 | 客户信息 CRUD，三级地址联动（国家→城市→地址） | customer, address, city, country |
| 库存管理 | 按门店/影片查询拷贝，管理 inventory 增删 | inventory, film, store |
| 电影管理 | 影片信息 CRUD，管理分类关联（film_category），管理演员关联（film_actor） | film, film_category, category, film_actor, language |
| 演员管理 | 演员信息 CRUD，查看参演作品列表 | actor, film_actor, film |

## 第三章 系统实现

### 3.1 登录系统实现

**界面设计**：
- 登录窗口居中显示，标题为"Sakila DVD 租赁管理系统 — 登录"
- 用户名输入框 + 密码输入框（掩码显示）
- 登录按钮 / 退出按钮
- 按 Enter 键快捷登录

**登录流程**：
```
用户输入用户名+密码 → 查询 staff 表
  ├── 无匹配 → 提示"用户名或密码错误"
  ├── active=0 → 提示"账号已停用"
  └── 验证通过 → 记录 staff_info → 关闭登录窗口 → 显示主界面
```

**验证规则**：
- 用户名为空 → 提示"用户名不能为空"
- 密码为空 → 提示"密码不能为空"
- 用户不存在或密码错误 → 提示"用户名或密码错误"
- 登录成功 → 提示"欢迎 {姓名} 登录系统"

**角色路由**：
- 从 staff 表读取 store_id，门店 1 和门店 2 的店员均可访问全部功能模块
- 后续可扩展：为 staff 表增加 role 字段区分店员/经理

### 3.2 租赁处理模块

**界面设计**：
- 顶部：客户搜索区（按姓名/邮箱模糊查询）→ 客户选择列表
- 中部：库存拷贝选择区（按影片名/门店查询）→ 可用拷贝列表
- 下部：租赁中记录列表 + 归还按钮
- 操作：选择客户 + 选择拷贝 → 点击"租出" → 自动生成 rental + payment 记录

**业务规则**：
- 仅可选择当前未被租出的拷贝（无 return_date=NULL 的 rental 记录）
- 租出时自动记录当前时间为 rental_date，付款金额 = film.rental_rate
- 归还时自动更新 return_date = 当前时间
- 客户有未归还记录时不可删除

### 3.3 客户管理模块

**界面设计**：
- 表单区：名、姓、邮箱、地址（三级联动下拉框：国家→城市→地址）、门店、活跃状态
- 按钮区：查询、添加、修改、删除
- 表格区：ID、姓名、邮箱、地址、城市、国家、活跃

**三级地址联动**：
```
选择国家 → 筛选城市 (city.country_id)
选择城市 → 筛选地址 (address.city_id)
选择地址 → 填充完整地址信息
```

**业务规则**：
- 邮箱格式校验
- 有未归还 rental 记录的客户不可删除
- 删除客户前弹窗确认

### 3.4 电影管理模块

**界面设计**：
- 表单区：片名、简介、发行年份、语言、租期、日租金、片长、替换成本、分级、特色
- 分类管理子区：多选框（Action/Comedy/Drama 等 16 分类）
- 演员管理子区：已关联演员列表 + 添加/移除按钮
- 按钮区：查询、添加、修改、删除
- 表格区：ID、片名、分级、分类、片长、日租金

**多对多关系处理**：
- film_category：增删改时同步维护 category 关联
- film_actor：增删改时同步维护 actor 关联

### 3.5 库存管理模块

**界面设计**：
- 查询区：按门店（store）和影片名筛选
- 表格区：拷贝ID、影片名、所属门店、当前状态（在馆/已租出）
- 添加按钮：新增拷贝到指定门店

**业务规则**：
- 已被租出（rental 中 return_date=NULL）的拷贝不可删除
- 添加拷贝仅需选择影片 + 门店
